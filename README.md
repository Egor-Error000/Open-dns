# Open DNS

Self-hosted DNS over HTTPS и выборочное TLS-реле на Ubuntu 24.04:
dnsdist 1.8 + nginx stream. Проект не предоставляет готовый DNS-сервис.
Для работы нужен собственный VPS, домен и сертификат.

В репозитории используются только примеры: `192.0.2.1` и `dns.example.com`.
Настоящие параметры создаются локально и исключены из Git. При отсутствии
локального конфига доступны сборка примеров и тесты; сетевые проверки
и развёртывание завершаются до подключения к серверу.

## Начало работы

Нужен Node.js 20 или новее. Сторонних npm-зависимостей нет.

```powershell
npm test
npm run build
npm run check:public
Copy-Item config/server.example.json config/server.json
```

В `config/server.json` указать **свой** публичный IPv4, DNS-имя и `sshUser: "root"`.
Затем повторить `npm run build`. Не добавлять рабочий конфиг через `git add -f`.
Установка на VPS описана в [docs/operations.md](docs/operations.md).

Каталог `config/services.json` содержит выбранные домены. `exact` выбирает
только указанное имя; `suffix` — имя и его поддомены с границей DNS-метки.
Один генератор создаёт согласованные настройки dnsdist, nginx, YogaDNS
и HTML-инструкцию. Готовые файлы находятся в игнорируемой папке `build/`.

## Структура

- `config/server.example.json` — безопасный пример параметров.
- `config/server.json` — локальные рабочие параметры, вне Git.
- `config/services.json` — каталог выбранных доменов.
- `src/` — загрузка параметров и генератор.
- `server/` — установка, обновление, откат, firewall и сертификаты.
- `scripts/` — развёртывание, ручные сетевые проверки и проверка публичных файлов.
- `client/setup.template.html` — шаблон пользовательской инструкции.
- `tests/` — автономные тесты и Linux-проверка firewall в отдельном net namespace.
- `docs/operations.md` — обслуживание сервера; `SECURITY.md` — модель доступа и публикация.

## Обновление и проверки

После настройки собственного сервера:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/deploy.ps1
npm run check:dns
npm run check:https
npm run check:boundaries
```

Настройки Firefox и YogaDNS пользователь применяет вручную по `build/setup.html`.
Перед импортом `build/YogaDNS-SmartDNS.xml` сохранить свой прежний профиль.
Скрипты не меняют системный DNS и не импортируют клиентские профили автоматически.

## Как работает доступ

Выбранные DNS-имена получают IPv4 вашего VPS; nginx пересылает TLS по SNI
только для каталога доменов. Остальные имена разрешаются обычным образом.
Клиент проверяет сертификат целевого сайта; TLS-содержимое реле не расшифровывает.

Эта версия открывает DoH и реле любым IPv4-клиентам. **Клиентской авторизации,
ключей доступа, индивидуальных квот и защиты от DDoS в проекте нет.**
Домен и IP не являются секретом или паролем. Доступность общего реле может
расходовать ресурсы и трафик вашего VPS; решение о публичном доступе принимает оператор.

UFW пропускает TCP 22/80/443 и запрещает остальные входящие соединения.
DNS и внутренний DoH слушают только loopback; публичного UDP/TCP DNS на 53 нет.
Защита nftables ограничивает исходящие соединения nginx во внутренние сети.
HTTP/3, ECH и IPv6-реле не поддерживаются. Ограничение по SNI не различает URL
внутри одного домена. Работу входа в аккаунты и API проверяет оператор отдельно.
