# Безопасность

## Публикация исходников

В Git хранится только `config/server.example.json` с адресами для документации.
Рабочий `config/server.json`, сборки, журналы, резервные копии, сертификаты,
приватные ключи и записи трафика исключены из Git. Сборка может содержать ваши
настоящие адреса: не публикуйте папку `build/` или рабочую HTML-инструкцию
как демонстрационный артефакт, если хотите сохранить параметры размещения приватными.

Перед каждым коммитом:

```powershell
npm run check:public
git diff --cached
git status --short
```

Проверка ищет неожиданные IP, типовые секреты и запрещённые пути в отслеживаемых
и новых неигнорируемых файлах. Это дополнительный барьер; проверка не доказывает
отсутствие всех возможных секретов, сведений о размещении или утечек в старой истории.
Не обходите `.gitignore` через `git add -f` для рабочих данных.

Если секрет уже попал в Git, удаление из последнего файла не удаляет его из
истории: отзовите/замените секрет и отдельно очистите историю и опубликованные копии.
Не прикладывайте к публичным issues свои SSH-ключи, адреса личной инфраструктуры,
полные конфиги, журналы с IP пользователей или содержимое аккаунтов.

## Модель сервиса

DoH и TLS-реле доступны любому IPv4-клиенту. Адрес сервера не заменяет авторизацию.
Список доменов ограничивает назначения реле, но не ограничивает круг клиентов.
Проект не реализует учёт пользователей, квоты, защиту от перегрузки или DDoS.
Оператор должен осознанно выбрать публичный доступ и следить за трафиком и ресурсами.

Сервер не расшифровывает TLS целевых сайтов. Собственный DoH завершается на dnsdist:
оператор DNS видит запросы. Firefox может отправлять ему запросы для всех сайтов,
даже когда через TLS-реле идут только выбранные домены.

nginx пишет IP, SNI, upstream, объём и длительность соединения. Содержимое HTTPS,
пароли и URL-пути сайтов в stream-журнал не попадают. Ограничьте доступ к логам
и настройте срок хранения. Не отключайте проверку TLS в клиентах.

## Администрирование

Проверяйте SSH host key через консоль провайдера. Установщик требует рабочий вход
root по ключу, отключает пароли SSH и использует порт 22. Сохраняйте резервный
доступ через консоль перед изменением firewall. Установка рассчитана на чистый
Ubuntu 24.04; не применяйте её к серверу с посторонними сервисами без проверки.

Не открывайте служебные 5300/8443 и публичный DNS 53. Сохраняйте защиту внутренних
назначений nginx. Обновления доменов имеют отдельный откат; первая установка
сохраняет копии конфигов, но не является полным снимком системы.
Поддерживайте ОС, nginx и dnsdist в актуальном состоянии и контролируйте ACME.
